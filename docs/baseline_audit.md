# Detection-adapted unlearnable-example baseline audit (pre-registered, 2026-09-28)

This document records the four **classification** methods that are being adapted to a selective VOC20/person **detection** task. None of the official repositories reports these four VOC detection runs. The original papers and repositories are evidence for mechanisms, not for our future detection results. The four supplied PDFs were read alongside pinned official code. No clean validation images or final victim AP were used to select variants or hyperparameters.

## Shared detection adaptation and evaluation lock

The separate [`protocol_lock.json`](../protocol_lock.json) freezes the data, surrogate **initial** checkpoint, spatial support, victim, and AP50 evaluation. The 16,551-image training split has 6,095 images and 13,256 GT objects labelled person (VOC ID 14); all 6,095 person images will be perturbed and all other training images copied byte-for-byte. All labels remain byte-for-byte identical. The 4,952-image validation split remains clean.

Each image has a **sample-specific** perturbation tensor because GT layouts differ. In the union of person GT boxes the pre-mask perturbation is clamped to ±8/255. At any person/non-person GT overlap it is multiplied by 0.5, giving ±4/255. It is zero outside the person union. These support rules are a common **detection adaptation**, not native to any paper. They are applied during differentiable optimization and again at materialization; final decoded pixels must independently pass an integer-budget audit. No labels are removed from the future victim training dataset. For an EM-family attack objective, however, only person GT enters the *attack loss*; this excludes non-person targets from the attack objective while allowing full image context in the detector forward.

The shared target-conditioned learning objective calls the installed Ultralytics YOLO detection criterion with **person GT only**. The criterion's BCE is restricted to the **person logit channel only**: merely dropping non-person GT would still treat their 19 class logits as negatives, an unintended non-target attack signal. The person-GT assignment, matching box and DFL terms, and the same locked YOLO weights (box 7.5, class 0.5, DFL 1.5) are retained. This is the closest task-level substitute for the original supervised classification loss: it measures whether the surrogate learns to detect the retained target GT. A targeted unit test verifies zero classification gradient on the other 19 logits, and all four final sanities use this repaired objective. The three EM-family methods share that exact objective; their inner optimization and surrogate dynamics distinguish them. GT boxes are converted through the same letterbox geometry as the input image. The clean VOC-pretrained YOLO checkpoint is common initial surrogate state; EM/REM/SEM update it, while EntF freezes it as a reference. No K-background, L_BG, L_rel, L_ret, adaptive learner, TSFL, L_orth or other Ours-specific mechanism is imported.

The matched clean baseline is complete and stored in `protocol_lock.json`: random-init YOLOv8n, seed 0, 200 epochs, batch 36, 640 input, and locked training settings on 16,551 clean VOC train images with 4,952 byte-identical clean validation images. Its AP50 is 0.865875 for person, 0.771233 mean over non-target classes, and 0.775966 overall; person recall is 0.749406. The selected `best.pt` SHA256 is `6685e28503345bf6333452356758c09e002e5698a8f16e7db753ae65456722b2`. The prior Experiment A victim remains unmatched because its optimizer and training settings differ. The existing epsilon-16/255 Ours results are **not** eligible for an epsilon-8/255 main table. Existing epsilon-8/255 Ours data may enter the table only if its full protocol and decoded-pixel audits match this lock.

## EM-Det: sample-wise error minimization

- **Original task / variables / core loss:** supervised image classification; a trainable surrogate `θ` and sample-wise perturbations `δ_i`; alternating descent in `θ` and `δ` on cross-entropy, i.e. `min_θ min_{||δ_i||∞≤ε} CE(f_θ(x_i+δ_i), y_i)`. This is **min-min**, not an adversarial inner maximization.
- **Original code behavior:** `sample_wise_perturbation` trains the current surrogate on currently perturbed samples for `train_step` batches, then runs `min_min_attack` with model weights fixed while updating each `δ_i`. It repeats until the training-error stop condition, with 0.01 the README sample-wise default. The surrogate is not reset between these cycles in that path. There is no separate clean reference model, robust inner loop or required EOT sampler.
- **Original main variant / budget / schedule:** README sample-wise CIFAR-10, 8/255, 20 PGD descent steps of 0.8/255 per noise update, `train_step` default 10, stop error 0.01. Class-wise noise is a separate variant and is **not** selected here because one shared class tensor cannot align to variable-size person-box unions without a second placement convention.
- **Detection adaptation:** one `δ_i` per target-containing detection image; `CE` becomes the shared person-GT YOLO detection loss; full image is forwarded, person GT only enters the loss. The common spatial projection is added. The detection training-error proxy is `1 - person-GT recall` on **poisoned training images** at confidence 0.25 and IoU 0.5, using the same 640-pixel letterbox. This is a stopping proxy, not clean-validation AP. The locked implementation includes the sequential 10-minibatch sample-wise surrogate phase, one full target-image min-min pass, and train-only error evaluation; it records whether the ≤0.01 stop threshold was met after the authorized single cycle.

## REM-Det: robust error minimization

- **Original task / variables / core loss:** supervised classification with trainable `θ`, per-sample defender `δ_i`, adversarial perturbation `a`, and stochastic transforms `T`. Defender update minimizes an expectation of **maximized** classification error: `min_δ E_T [max_{||a||∞≤ρ} CE(f_θ(T(x+δ)+a), y)]`, while the surrogate trains on adversarially attacked defended images. This is robust min-max **inside** the error-minimizing poison process, with joint surrogate/defender dynamics.
- **Original code behavior:** `RobustMinimaxPGDDefender` runs an adversarial PGD **ascent** for every EOT sample inside each defender PGD descent step. `generate_robust_em.py` trains the surrogate on adversarially perturbed defended samples. Simply adding random augmentation to EM would omit the defining max operator.
- **Original main schedule:** official CIFAR-10 command: 5,000 surrogate steps, defender radius 8/255 with 10 steps of 1.6/255, adversarial radius 4/255 with 10 ascent steps of 0.8/255, five EOT samples, perturb-frequency 1; SGD surrogate LR 0.1 with scheduled decay. This large classification schedule is **not** automatically presumed feasible at 640-pixel YOLO resolution.
- **Detection adaptation:** use the same person-GT YOLO loss as EM-Det, the same final-poison 8/255 support and a method-internal adversarial radius **4/255** (kept at the official 1:2 ratio). Following the original robust attack, this ephemeral inner adversarial variable may act over the whole image; only the persistent **defender poison** is spatially restricted. Defender descent and adversarial ascent remain separate computations; surrogate training remains adversarial. No full schedule may be chosen using final validation AP.

## SEM-Det: stable error minimization

- **Original task / variables / core loss:** supervised classification with trainable `θ` and per-sample defender `δ_i`; the **defender** minimizes the expected classification error under sampled **uniform random** perturbations `r~U[-ρ,ρ]` and stochastic transforms, rather than REM's inner adversarial `max_a` for defender optimization. The surrogate **still trains adversarially** using a PGD attacker in the official `generate_stable_em.py` path.
- **Original code behavior:** `StablePGDDefender` replaces REM's inner adversarial PGD call with a random uniform draw at each EOT sample. Its defender objective is sample expectation; REM's is adversarial maximum. Both have an adversarially trained surrogate, but the defender gradients and forward/backward counts differ. Changing a method label without changing this computation would be an invalid baseline.
- **Original main schedule:** README CIFAR-10 command uses the same 5,000 surrogate steps, 8/255 defender, 10 defender steps at 1.6/255, 4/255 sampling radius, five samples, and 4/255 / 10-step adversarial surrogate training as REM.
- **Detection adaptation:** the uniform random stability samples and person-GT YOLO loss replace classification samples/loss. As in the original stable-training mechanism, the ephemeral stability samples may cover the whole image; the final defender perturbation alone follows the common 8/255, overlap-4/255, outside-zero projection. Its internal randomness is seeded and logged.

## EntF-Det: pre-registered Push recipe

- **Original task / variables / core loss:** supervised classification; train a clean reference (the official README recommends a robust reference), extract clean feature embeddings, compute class centroids, freeze the reference, then optimize per-sample poison. **Push** minimizes the negative MSE to the sample's own-class clean centroid, moving poisoned features away. **Pull** minimizes positive MSE to a chosen other-class centroid; it is a different recipe, not an outcome-based fallback. There is no min-min surrogate update or adversarial inner loop in the Push poison objective.
- **Original main variant / budget / schedule:** official README command uses `--eps 8 --recipe push`; `utils/options.py` defaults also choose `push`, `attackoptim=PGD`, `attackiter=300`, `tau=0.05` times ε, random initialization and one restart. Paper reports Push as its subsequent main choice, so **EntF-Push-Det is pre-registered**. Pull will not be selected later based on victim AP.
- **Detection adaptation:** use the common clean VOC-pretrained YOLO detector as **frozen reference** (recording that this is not a separately robust-trained reference). The production mini sanity measured exact module `model.15`, feature shape **80 × 80 × 64** at 640-pixel letterboxed input. Each person GT rectangle is transformed through the same letterbox geometry, converted to an area-interpolated feature-grid mask, and its feature vector is a weighted spatial mean. Average all train-split person-object features into one **person-class centroid**, not a background prototype. The mini sanity used 5 images only; the official centroid must include all 13,256 train person objects. Push each poisoned person ROI away from that clean target centroid under the common spatial mask. No non-target class centroid is needed for Push; such centroids are only part of Pull, which is not selected.

## Pre-registered implementation gates and limits

The official repos use small classification inputs and their own learning schedules. The user set an **8-hour wall-clock cap for each method's noise generation** and subsequently clarified that the cap cannot justify changing the defining inner/outer structure, loss, or sampling mechanism. The earlier shortened inner-step proposal in the Section 33 report is **superseded and was never used for a full run**. The revised [schedule diff](baseline_schedule_diff.md) retains complete method-internal loops and considers only fewer complete optimization cycles and memory-supported minibatch changes. The completed 5-image mini sanities used EM: one surrogate plus two defender steps; REM: two defender steps × two EOT samples × two adversarial ascent steps plus a two-step adversarial surrogate update; SEM: two defender steps × two uniform samples plus a two-step adversarial surrogate update; EntF: three Push steps and a five-image clean centroid. These are validation-only reductions, not hidden formal schedules. A 5–20-image mini sanity is implementation validation, **not** an AP or efficacy estimate. The matched clean baseline and one-cycle schedules are now locked. The authorized four-method sequence will stop at the first generation, materialization, audit, or victim failure; it will not report incomplete cycles as completed methods.
